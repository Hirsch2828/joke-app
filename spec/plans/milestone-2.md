# תוכנית Milestone 2: בדיחה מ-GPT-5

## המטרה
הבדיחה מגיעה מ-GPT-5 דרך הפונקציה, והמפתח נשאר בשרת. הדף כבר מדבר עם הפונקציה (Milestone 1), אז כמעט כל העבודה היא ב-`api/joke.js`, ועוד תיקון קטן אחד בדף.

## מצב התחלתי (מהקוד)
- `api/joke.js`: מחזיר בדיחה זמנית, חותך נושא ל-100, גוף שבור = אין נושא, ויש `console.log`.
- `index.html`: ארבעת המצבים, הדמויות, "עוד בדיחה!" ו"לנסות שוב" כבר קיימים. כשהשרת מחזיר שגיאה, הדף מציג כרגע הודעה כללית ("משהו השתבש") ולא את `error` מהשרת.
- המפתח כבר ב-Vercel. אין צורך ב-Redeploy אחרי ה-push.

## שלב 0: לקרוא תיעוד עדכני (לפני שכותבים קוד)
לפי ARCHITECTURE.md סעיף 4, לבדוק בתיעוד של OpenAI ושל Vercel:
- מבנה הבקשה ל-Responses API (`model`, `instructions`, `input`, `reasoning`, `max_output_tokens`).
- האם `reasoning: { effort: "low" }` נתמך ב-`gpt-5`. אם לא, מורידים אותו.
- מבנה התשובה: `output_text`, או `output` ← פריטי `message` ← חלקי `output_text`.
- קודי השגיאה (401, `insufficient_quota`, מגבלת הוצאה, 429, 404) והסטטוסים שלהם.
- ש-`export default { fetch }` בפונקציה של Vercel עדיין הצורה הנכונה.
- ערך סביר ל-`max_output_tokens`: ב-GPT-5 זה כולל גם את ה"חשיבה", אז ערך נמוך מדי יחזיר תשובה ריקה.
אם התיעוד סותר את ARCHITECTURE.md, לעצור ולהגיד למשתמש לפני שמשנים.

## שינויים ב-api/joke.js
- נשאר: POST בלבד (405 אחרת), חיתוך ל-100, גוף שבור = אין נושא, JSON תמיד, בלי CORS.
- מפתח חסר (`process.env.OPENAI_API_KEY` ריק): `{ error: "חסר מפתח בשרת" }`, סטטוס 500, ושורה ב-`console.error`.
- הקריאה: `fetch` אל `https://api.openai.com/v1/responses` עם `Authorization: Bearer ...`.
  - `model`: `process.env.OPENAI_MODEL || "gpt-5"`.
  - `instructions`: הפרומפט המרכזי מ-ARCHITECTURE.md, מילה במילה.
  - `input`: "נושא הבדיחה: [הנושא]", או "אין נושא. ספר בדיחה כללית על החיים."
  - `reasoning` ו-`max_output_tokens` לפי התיעוד.
- שליפת הטקסט: `output_text` אם קיים, אחרת מחלקי `output_text` בפריטי `message`. אין טקסט = שגיאה.
- תשובה מוצלחת: רק `{ joke }`, סטטוס 200.
- שגיאות, הודעה קצרה בעברית (502, או 500 כשהבעיה אצלנו), והפרטים (סטטוס וקוד, לא המפתח ולא כל הגוף) ב-`console.error`:
  | המצב | ההודעה |
  |---|---|
  | 401 | המפתח לא תקין |
  | נגמר הקרדיט | נגמר הקרדיט בחשבון OpenAI |
  | מגבלת הוצאה | הגענו למגבלת ההוצאה החודשית |
  | 429 | יותר מדי בקשות. נסו שוב בעוד רגע. |
  | 404 (שם מודל שגוי) | המודל לא נמצא. כדאי לבדוק את OPENAI_MODEL |
  | שגיאת רשת | אין חיבור ל-OpenAI כרגע. נסו שוב. |
  | כל דבר אחר | משהו השתבש. נסו שוב. |
- `console.log` לכל בדיחה: הנושא והמודל. לעולם לא המפתח, ואף פעם לא את התשובה של OpenAI עם כותרות.
- הטקסט הזמני "בדיחה זמנית מהשרת" ו"המפתח: נמצא/חסר" נמחקים.

## שינויים ב-index.html
- כשמגיעה שגיאה, להציג את `data.error` מהשרת (ב-`textContent`), ולהשאיר את "משהו השתבש. נסו שוב." רק כשאין הודעה (למשל נפילת רשת).
- שאר המצבים והאנימציות כבר בנויים לפי DESIGN.md. לוודא בבדיקה שכל ארבעת המצבים נראים כמו ה-mockups, ולתקן סטיות קטנות אם יש.

## מה המשתמש עושה בידיים
1. **לפני הקוד:** לוודא בחשבון OpenAI שיש קרדיט, ש-Auto recharge כבוי, ושיש מגבלת הוצאה חודשית. המפתח התקבל ממישהו אחר, אז ייתכן שאת ההגדרות האלה רואה רק בעל החשבון. אם אין לך גישה, שואלים אותו.
2. אחרי ה-push: בדיקות 1-3 ו-5-6 באתר החי (בטלפון).
3. בדיקה 4: ב-Vercel להגדיר `OPENAI_MODEL` עם שם שגוי, Redeploy, לבדוק, ואז למחוק את המשתנה ולעשות Redeploy שוב. Claude מנחה צעד אחר צעד.

## בדיקות עצמיות של Claude (בלי מפתח)
- הפונקציה ללא מפתח: מחזירה "חסר מפתח בשרת" (500).
- הרצה מול OpenAI כשהמפתח מזויף בסביבת התהליך בלבד (לא נכתב לשום קובץ ולא מוצג): אמורה לחזור "המפתח לא תקין". מוודא את מפת השגיאות ואת הלוגים.
- בדיקת שליפת הטקסט על תשובות לדוגמה של שני המבנים.
- הדף בדפדפן ברוחב 375/390 עם שרת בדיקה זמני בתיקיית ה-scratchpad, כולל שגיאה אמיתית מהשרת.
- חיפוש בקוד: אין `sk-`, אין מפתח, אין CORS, אין `innerHTML`, והדף לא פונה ל-`api.openai.com`.
- אין בדיקה של בדיחה אמיתית אצל Claude: זה דורש את המפתח, והוא רק ב-Vercel. את זה בודק המשתמש.
